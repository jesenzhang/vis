# 自主基准测试、自动评测系统、测评方法及指标计算

**语音专项技术响应 · 评测与验收附章 V2.0**

> 本章定义如何证明“多语种实时识别、转写、合成与智能讲解”和“识别准确率≥95%”，不声称当前已通过该要求。每个合同语种须独立验收。

## 1. 测试体系

采用三级体系：
1. **PUBLIC公开标准基准**：公开且可核验版本的标准语音语料，作用是给出算法评测方法与横向参考。
2. **LOCAL自主业务基准**：实际录制的授权数据，覆盖讲解场景、专业术语、方言/口音、设备和噪声。
3. **ACCEPTANCE独立验收**：事前封存的Holdout，既未用于模型选型/调参，也未由工程人员查看其金标准，满足招标方约定样本和环境条件。

以上三级独立出具统计表，不将公共集的结果列为“我方实际准确率”，也不根据测试结果倒选评价公式。

## 3. 自主识别准确率定义

采用人工金标准文本的编辑距离错误率：

**WER = (S + D + I) / N × 100%**

**CER = (S_c + D_c + I_c) / N_c × 100%**

- S：替换，D：删除，I：插入；N：人工参考文本的词数；下标c表示字符。
- **按编辑距离定义的识别正确率 = 100% − WER或CER**（存在极端情况下可能小于0的理论情况）。该指标不等于“整句完全匹配率”。
- 整句完全正确率另计算为完全匹配的句数/有效句数。
- 语种识别准确率=正确识别语种数/有效样本数。
- 专业术语或命名实体正确率按人工标记的关键实体及预先固定的匹配规则计算。

**样例（纯计算示意，并非本项目实测）**：参考中文字符N_c=1000，替换20、删除15、插入10，则CER=(20+15+10)/1000=4.5%，编辑距离意义的正确率=95.5%。

**聚合**：先把某语种全部有效样本的S/D/I/N分别相加，再计算语料级CER/WER；不能简单平均句级百分数。按语言、噪声、设备、说话人、术语场景分别报告，另外记录处理失败和无输出的单独数量。

**归一化**：事先冻结Unicode、大小写、数字/日期、标点、空格、简繁、语种分词与专有实体政策；不能测试结束后删除错误字词或者临时采用得分较高的计量方式。

**验收口径**：根据招标条件，拟以每个约定语种的CER或WER≤5%判断“识别准确率≥95%”；每个语种对应选用CER还是WER，应与招标方确认并在首次正式测试前冻结。当前五语种仅为数据构建示例，不视为招标指定语种数量。

## 4. 统计有效性与置信区间

- 提供每语种独立样本数、说话人数、音频小时数、音频条件、参考字/词数、S/D/I计数、失败/排除数。
- 建议采用**说话人聚类Bootstrap**（例如≥2000次）估计语种错误率的95%置信区间；同一说话人的相关音频不能当作独立个人。
- 增强副本不得当成新的独立说话人或额外原始录音，避免置信区间虚假变窄。
- 合同要求若仅明确CER/WER阈值，置信区间上界≤5%可以作为内部高置信质量门槛，不可未经确认擅自替换法定/合同验收标准。
- 评分系统异常、金标准缺失、GPU OOM、服务超时标为INCOMPLETE或单独技术失败，不能隐性过滤以获得高于95%的结果。

## 5. TTS与声音克隆

| 指标 | 公式及方法 | 关键控制 |
|---|---|---|
| 内容错误率 | 合成音频经固定独立ASR转写后的WER/CER | 记录独立ASR误差、测试语言 |
| 主观自然度MOS | 有效1–5分盲评总分/评分人数 | 正式样本建议≥5位评价者、报告CI |
| 声纹相似度SIM | 参考/合成语音特征向量余弦u·v/(||u||||v||) | 固定说话人嵌入模型和版本，不代表“相似概率” |
| ABX听辨 | 人工听辨正确数/有效听辨数 | 随机化播放、均衡音量和说话人 |
| TTS首包延迟 | 合成请求被接收到首个可播放音频块 | 报P50/P95/P99 |
| 合成RTF | 推理耗时/生成音频时长 | 固定精度、批大小和设备 |

设置不同授权参考录音长度（如3秒、5秒、10秒）、口音、噪声、跨语种情况；检查非法授权、过期和撤销状态下必须拒绝。MOS、SIM和内容准确率分别出表，不混成一个“语音克隆准确率”。

## 6. 安全审核与事实核查

**安全分类**：
- Precision = TP/(TP+FP)
- Recall = TP/(TP+FN)
- F1 = 2×Precision×Recall/(Precision+Recall)
- 误拦截率FPR = FP/(FP+TN)
- 漏检率FNR = FN/(FN+TP)

分别报告正常业务数据和高风险挑战数据，不能用整体F1推断“风险全部通过”。安全风险门槛按合同和危害类别明确。

**事实核查**：
- 事实支持率 = 正确被指定证据支持的原子事实数 / 参与评测的原子事实总数。
- 引用准确率 = 正确且相关的证据引用数 / 全部输出引用数。
- 已知错误检出率 = 被正确识别的金标准错误条目数 / 金标准错误条目总数。
- 正确拒答率 = 对无充分证据问题正确拒绝数 / 应拒绝问题总数。

要求记录SUPPORTED、CONTRADICTED、INSUFFICIENT及核查超时四类情况；不得将“未知/无法验证”计入SUPPORTED。核查系统故障时禁止确定性播报。

## 7. 实时识别、讲解与负载评测

| 指标 | 定义 | 评价说明 |
|---|---|---|
| ASR RTF | ASR处理耗时 / 输入音频时长 | 小于1仅说明特定单路配置快于实时 |
| ASR终稿延迟 | 用户发言结束至final文本就绪 | P50/P95/P99 |
| TTS首包延迟 | TTS请求开始至首个可播放音频块 | P50/P95/P99 |
| E2E首声响应 | 用户发言结束至终端收到可播放语音 | 明确缓存讲解/动态核查不同链路 |
| 会话成功率 | 完成有效会话/所有发起有效会话 | 同时报超时、取消、断连 |
| 请求失败率 | 失败有效请求/全部发起有效请求 | 失败不得剔除后只报成功请求延迟 |
| 有效并发 | 满足约定延迟/失败率/连续播放的最大会话数 | 必须压力测试测得 |
| GPU峰值显存 | 实际推理过程的峰值占用 | 按运行后端记录 |

测试逐级1/2/4/8/16/32路，预热后每档稳态≥15分钟；再进行≥24小时稳定性测试，包含网络抖动、重连、语音打断、GPU OOM、依赖服务故障、缓存失效和核查超时。测试门槛在标书定稿前与实际服务器规格及合同确认。

## 8. 测试步骤

### 8.1 ASR准确率

冻结Gold和标准化规则 → 验签数据集 → 配置同一编码采样率 → 输入真实语音 → 保存原始prediction/失败 → 计算每条S/D/I/N → 按语种微平均与场景分组 → 输出错误样本、准确率、置信区间与复现脚本。

### 8.2 实时ASR

通过模拟客户端分帧发送音频，同时记录asr.partial、asr.final、丢帧、时钟和延迟，复测连续发言、短暂停顿、语言切换、网络抖动与断连重建。

### 8.3 TTS/声音克隆

使用冻结文本、获得授权的参考音色、相同推理参数合成音频，进行MOS盲评、SIM、ABX、合成转写错误率及TTFA统计，测试失效授权拒绝及音频合成标识。

### 8.4 三重核查

使用含金标准标签的正常/风险文本与事实证据题组，计算安全P/R/F1、事实支持/引用/错误检出/拒答及不同错误类别。以异常/伪造引用/证据不足等挑战样本验证发布门禁。

### 8.5 E2E与联调

完整发送多轮问题语音→识别→知识问答→三重核查→TTS→字幕/语音播放，模拟第三方API鉴权、错误码、限流、断线/打断与持续压测，保存trace_id。

## 9. 每次基准输出与报告格式

保存run_manifest.json、predictions.jsonl、errors.jsonl、metrics.json、metrics_by_language.csv、hardware.json、latency.csv、failure_cases.csv、report.md、evidence_index.json、screenshots/。

结果状态：**NOT_RUN / RUNNING / PASS / FAIL / INCOMPLETE**。只有已经运行且数据完整、达到冻结门槛时才能标PASS；OOM、缺失Gold、样本处理失败导致报告不完整标INCOMPLETE。报告中PUBLIC与LOCAL/ACCEPTANCE列分开。
