# 自建测试数据集构建、数据说明与截图证明

**投标语音专项 · 自主评测数据及证据设计V2.0**

> 此文只规定数据建设及证据证明的方法；目前实际录音、标注、语种实测和截图**尚未作为本标书证据采集完成**。不得把表中的规划量填写为“已建成样本量”。

## 1. 数据集构成与来源

采用三条互补路线：

1. **公开标准语料**：以有公开文档、语种、版本、Gold文本和许可的语音数据集，提供评测标准可比性。
2. **自主授权录音**：由招募的真实说话人使用目标终端和实际应用环境录制，提供业务相关性。
3. **专项挑战数据**：覆盖噪声、方言与口音、数字与专名、实时打断、多语种切换、安全违规、证据矛盾和知识缺失等边界条件。

可参考公开数据：FLEURS（https://huggingface.co/datasets/google/fleurs）、Common Voice（https://commonvoice.mozilla.org/）；另根据合同实际支持语言选对应公开测评集。**本章不提供任何具体模型公开准确率数值**，以避免上游公开成绩误写成VIS实测。公开数据访问必须核验许可及署名条件，不得擅自二次发布原始语音。

## 2. 规划数据规模（样例：五语种）

待合同确定语种清单后替换下表。每语种2,000条为**规划值**，非实测或已采集数字。

| 数据集 | 规模/来源规划 | 关键标注 | 评价目的 |
|---|---|---|---|
| 多语种ASR | 每语种2000条；公开600，自录1400；5语种共10000 | 人工Gold文本、语言、speaker、环境 | 识别准确率、场景分组 |
| ASR复杂环境 | 每语种≥400条，作为上述2000条子集 | 噪声、远场、设备、口音 | 鲁棒性 |
| ASR专业术语 | 每语种≥300条，作为上述2000条子集 | 业务实体/术语及标准写法 | 术语与数值准确 |
| TTS | 每语种250条文本 | 发音词、数字、情绪/停顿 | MOS、内容正确 |
| 声音克隆 | ≥20位获得合法授权的说话人 | 参考音频、授权ID、音色评价 | SIM、ABX、跨语种 |
| 安全审核 | ≥2000条 | 正常/高风险/边界风险类别 | Precision/Recall/F1 |
| 事实核查 | ≥1000个问题 | 原子事实、证据ID/版本、Gold标签 | 支持/冲突/不足 |
| 完整语音对话 | ≥100段多轮会话，约500轮 | 预期动作、打断/切换/核查 | E2E、稳定性和链路能力 |

若每段语音平均20秒，五语种10000条约55.6小时，实际总时长需以录制数据统计，不能以估算替代。说话人数量、录音环境和设备组成需与招标验收场景匹配。

## 3. 自主真实语音录制

### 3.1 说话人和录音计划

按语种招募能胜任该语言自然交流的真实说话人，可规划每语种≥35人、每人约40条以产生约1400条自录音频。覆盖不同性别声音、年龄段、语速、口音与常用设备类型；在收集这些特征时遵循最小必要原则，不记录与评价无关的敏感信息。

录音任务包括：
- 自然提问和回答；
- 真实讲解问答（名称、地名、年代、数字、术语）；
- 简短口令和长句；
- 安静室内、日常环境噪声、远场及回声条件；
- 约定的语种切换与混合表达。

每名参与者在录音前签署知情同意/数据使用许可，明确数据使用目的、评测范围、存储期限、撤销流程和是否允许音色克隆。**普通ASR录音授权不自动包含克隆授权**。录音参与者实名联系信息和可用于识别说话人的原始音频须分权限管理。

### 3.2 音频技术标准

保存原始采集文件、设备原生参数和sha256；处理衍生文件记录转换方式及哈希。统一供测数据建议16kHz、16bit、单声道PCM/WAV，其他编码在接口约定范围内单独测兼容性。记录duration_ms、language、环境标签、设备、场景、采集批次；超短静音/严重剪切样本依事前标准标记并留痕。

### 3.3 人工标注、双审与质量门禁

授权与来源登记 → 音频完整性检查 → 候选初转写（可选）→ 人工逐条听写Gold → 第二名语言标注员复核 → 差异仲裁 → 语种及专业术语标记 → 唯一ID/去重/哈希 → 分组 → 数据集版本封存。

- 验收集Gold要求100%双人复核，有争议样本须仲裁；不能凭另一个ASR的输出直接作为Gold。
- 删除/修正样本需保留审计，所有排除规则在评测前冻结。
- 模拟噪声、混响、速度扰动只作为增强压力数据；不能作为独立真人说话人数或单独把原样本数翻倍。
- 防止同一说话人、同一内容或相近增强副本进入互相禁止的数据分组。

### 3.4 数据集划分与权限

建议对自主录音按说话人分组：Development 60%、Regression 20%、Sealed Holdout 20%。**该比例是私有自主录音的划分规则**，不应擅自重组公开数据原发布者规定的训练/验证/测试切分。

Holdout数据的音频和Gold采用最小权限访问；模型选择人员不得获知Gold；正式验收前冻结并记录版本及哈希。若使用封存集调参，该集不再具备独立验收属性，需建立新的封存集。

## 4. 自主测试数据字段与示例

ASR样本字段包括sample_id、dataset_version、split、language(BCP47)、speaker_id(匿名)、audio_path、audio_sha256、duration_ms、sample_rate、reference_text、environment、device_type、scenario_tags、source、license_id、annotation_status。

```json
{
  "sample_id": "example-zh-000001",
  "dataset_version": "planned-asr-private-v1",
  "split": "development",
  "language": "zh-CN",
  "speaker_id": "anonymous-example-001",
  "audio_path": "audio/zh-CN/example-000001.wav",
  "audio_sha256": "<real_file_sha256_when_recorded>",
  "duration_ms": 5000,
  "sample_rate": 16000,
  "reference_text": "请介绍一下这件展品的历史。",
  "environment": "indoor_quiet",
  "device_type": "mobile",
  "scenario_tags": ["explanation", "history"],
  "source": "self_recorded",
  "license_id": "example-consent-id",
  "annotation_status": "verified"
}
```

**重要**：此JSON是Schema演示，音频不存在，sha256和授权ID为占位符，不属于已采集证明，不应截图作实测样本。

TTS/Clone记录固定合成文本、合法voice_id、consent_id、参考音频条件、合成音频哈希、评分员盲评信息、内容错误率；安全/事实数据额外记录risk_type、risk_level、gold_facts、evidence_ids、evidence_version、expected_decision。

## 7. 复现证据目录与保密

每个正式运行保存run_manifest.json、predictions.jsonl、metrics.json、metrics_by_language.csv、hardware.json、latency.csv、failure_cases.csv、report.md、evidence_index.json和screenshots/。保留引用URL、采集时间和许可清单。

不得将敏感音频、原始声纹、真人身份、授权文档、私有Holdout Gold或访问密钥提交公开Git仓库。标书展示采用脱敏统计、匿名ID、部分合法展示音频和授权的证明材料。

## 8. 第5项评分关联

第5项“提供评测方案与基准测试数据得0.5分”的技术论证应由 [评测方案](03-evaluation-and-test-methods.md) + 本文件的数据样本/来源 + 公开标准资料证明 + 项目实际测试表共同支撑。数据建设计划并不能单独证明识别准确率≥95%；未完成测试时必须如实说明。
