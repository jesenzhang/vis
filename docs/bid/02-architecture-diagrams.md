> 版本V2.0；本页图表属于**DESIGN设计图**，不可当作产品运行截图。标书定稿时可导出为SVG或高分辨率PNG，保留图号及说明。

## 图1：多语种语音系统总体架构

```mermaid
flowchart TB
    U["Web / 移动端 / 导览终端 / 第三方业务系统"]
    subgraph Access["终端接入与会话控制层"]
        G["统一 API / 鉴权 / 会话 / 限流"]
        A["音频解码 / 降噪 / 回声处理 / VAD"]
    end
    subgraph Speech["识别与智能交互层"]
        S["语种检测 / 多语种流式 ASR / 实时字幕"]
        D["会话状态 / 上下文 / 语义理解"]
        R["业务知识检索 / 智能讲解生成"]
    end
    subgraph Trust["AI生成内容可信控制层"]
        X["安全审核 → 事实核查 → 独立交叉复核"]
        P{"可信发布门禁"}
    end
    subgraph Output["个性化语音生成层"]
        T["多语种 TTS / 授权声音克隆"]
        O["可播放音频流 / 字幕同步"]
    end
    K[("版本化知识库及引用证据")]
    V[("音色资产 / 授权范围 / 撤销记录")]
    M["审计追踪 / 性能监控 / 评测报告"]

    U <-->|WSS/WebRTC/HTTPS| G
    G --> A --> S --> D --> R --> X --> P
    K --> R
    K --> X
    V --> T
    P -->|PASS| T --> O --> G
    P -->|REVIEW/BLOCK| F["预审核安全提示 / 人工处理"]
    F --> T
    G -.-> M
    X -.-> M
    T -.-> M
```

**图注**：语音处理、智能讲解与三重核查采用独立服务化接口；动态事实必须通过发布门禁才能进入语音合成。音色管理保留授权核验与撤销能力。

## 图2：三重核查与发布控制

```mermaid
flowchart TB
    A["候选智能讲解文本"]
    B["第一重：内容安全审核"]
    C{"风险判定"}
    D["第二重：原子事实与证据核查"]
    E{"证据结论"}
    F["第三重：独立交叉复核"]
    G{"交叉复核结论"}
    H["PASS：准许播报"]
    I["REVIEW：补证 / 修订 / 人工复核"]
    J["BLOCK：拒绝发布"]
    K[("受控知识库 / 权威来源 / 版本化证据")]

    A --> B --> C
    C -->|高风险| J
    C -->|低风险| D
    C -->|边界风险| I
    D <--> K
    D --> E
    E -->|SUPPORTED| F
    E -->|INSUFFICIENT| I
    E -->|CONTRADICTED| J
    F --> G
    G -->|核查一致| H
    G -->|待确认| I
    G -->|重大错误| J
```

**图注**：三重核查为“安全性、证据支持性、独立复核”三个不同判定层，不等同于同一事实连续调用三个模型进行投票。任一关键步骤异常采用安全降级。

## 图3：自主测试数据集构建流程

```mermaid
flowchart TB
    A["公开标准数据集"]
    B["自主授权真实录音"]
    C["安全 / 事实 / 对话挑战数据"]
    D["来源、授权及许可登记"]
    E["音频格式校验 / 音频哈希 / 去重"]
    F["人工标准文本与标签"]
    G["双人复核 / 争议仲裁"]
    H{"数据质量门禁"}
    I["按说话人、来源、版本分组"]
    J["Development 开发集"]
    K["Regression 回归测试集"]
    L["Sealed Holdout 封存验收集"]
    M["版本化Manifest / 统计报表 / 哈希签名"]

    A --> D
    B --> D
    C --> D
    D --> E --> F --> G --> H
    H -->|失败：修正或剔除并留痕| F
    H -->|通过| I
    I --> J
    I --> K
    I --> L
    J --> M
    K --> M
    L --> M
```

**图注**：模型调参不得访问封存验收集金标准；增强音频不能独立计入原始录音数；若某语种没有足够真实录音和双审金标准，该语种必须标注未达到正式验收准备条件。

## 图4：自动化测试与评测系统架构

```mermaid
flowchart TB
    A[("测试数据与人工金标准")]
    B["测试计划 / 配置 / 执行版本"]
    C["ASR批量/流式Runner"]
    D["TTS/Clone Runner"]
    E["Safety/Fact Runner"]
    F["实时对话/并发Runner"]
    G[("原始预测 / 时延日志 / 资源快照")]
    H["独立评分引擎"]
    I["CER/WER / MOS/SIM / P-R-F1 / P95 / 成本"]
    J{"结果门禁"}
    K["分语种基准报告 / 失败样本"]
    L["截图与证据索引 / run_id / 哈希"]

    A --> B
    B --> C
    B --> D
    B --> E
    B --> F
    C --> G
    D --> G
    E --> G
    F --> G
    G --> H
    A --> H
    H --> I --> J
    J -->|PASS / FAIL / INCOMPLETE| K --> L
```

**图注**：评测系统与被测语音服务逻辑解耦；原始输出持久化、评分器可单独重跑；OOM、超时、评分缺口不得作为合格结果。未运行属于NOT_RUN。
